# Ruby on Rails - Eco Benchmark

## Provenance and runtime

Adapted from [upstream PR #37](https://github.com/Boavizta/ecobenchmark-applicationweb-backend/pull/37),
commit `3cf6c4efa3da8ddadd1d89635f4b9940446861f4`, continuing PR #31.
Thanks to @arnaudlevy, @SebouChu, and @GuillaumeMathieu27140 for the original
implementation and Docker integration.

This variant uses **PostgreSQL**, not MySQL. It runs Ruby 4.0.9, Rails 8.1.4,
Puma 8, and the PostgreSQL image from this repository's `migrations/` directory.
The empty `ruby-ror-mysql/` directory remains a separate, unimplemented variant.

```sh
# From the repository root: isolated smoke benchmark, logs, and automatic cleanup.
python3 benchmark/smoke_services.py --service ruby-rails-pg --output results/ruby-rails

# Standalone service + database for manual use (localhost:8080).
docker compose -f service/ruby-rails-pg/docker-compose.yml up --build -d database service
# Original 2-VU / 1-minute benchmark workload.
docker compose -f service/ruby-rails-pg/docker-compose.yml run --rm runner
```

Containers run in production mode as a non-root user. `DATABASE_URL` and
`SECRET_KEY_BASE` are required; Compose provides local-only defaults. Never use
the benchmark password or secret for a deployment. Configure the pool through
`DATABASE_POOL_MAX`, and Puma threads through `RAILS_MAX_THREADS`.

Tests inside the built image:

```sh
bundle exec ruby test/responses_test.rb
# Only with DATABASE_URL pointing at a fresh disposable benchmark database:
RAILS_ENV=test bundle exec ruby test/api_test.rb
```

The API tests cover 23-list pagination, empty lists, task persistence, fractional
statistics, and strings containing JSON property names (which must not be altered).
They also assert the reference SQL scope: one INSERT for a list/task write and
one LEFT JOIN query for a list read, without parent-lookup SELECTs or extra sorting.
Database foreign keys enforce parent integrity. ORM transaction statements and
PostgreSQL's generated-UUID `RETURNING` remain documented framework differences.

### Specifities

#### Creation timestamp

To use `creation_date` as the creation timestamp instead of the Rails-default `created_at`, we set an alias in `app/models/application_record.rb`

```rb
class ApplicationRecord < ActiveRecord::Base
  # ...

  alias_attribute :created_at, :creation_date
end
```

#### Initial schema

The shared database image owns the benchmark schema. Startup does **not** run
Rails migrations or change that schema. The original Rails migration is retained
for reference; opt in with `RUN_MIGRATIONS=1` only for a separate standalone database.

#### Docker-Composer hostname

On the Docker-Compose network, the app is named "service", so the runner will make requests to "http://service:8080".

The benchmark image runs in production mode. The development host configuration
is retained for manual development.

#### SQL requests implementation

To respect the contribution guidelines, we use custom classes (in `app/lib` folder) to generate the responses for the GET requests.

As for the POST requests, the SQL requests generated by the ORM are pretty much the same, the only minor difference is that the `id` attribute is not present in the INSERT INTO as an input, but as the output of the request.

Thus, the request `INSERT INTO account(id, login, creation_date) values ($1, $2, $3)` becomes `INSERT INTO account(login, creation_date) values ($2, $3) RETURNING id`.
